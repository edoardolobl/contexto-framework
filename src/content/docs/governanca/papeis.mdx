title: Responsabilidades
description: Quem explicita, aprova, publica e utiliza as informações, sem transferir decisões de negócio para a engenharia.

O framework é mantido por uma pessoa. **Os documentos que cada organização produzir a partir dele continuam sendo responsabilidade das respectivas áreas.** Não há uma transferência automática de autoridade para o mantenedor do portal.

## Papéis de referência

| Papel | Decisão ou responsabilidade |
|---|---|
| Especialista do domínio | Apresenta regras, exemplos, exceções e pontos ainda não definidos |
| Quem aprova | Confirma definições e aprova o documento no domínio |
| Governança | Resolve hierarquia de fontes e define políticas de revisão e acesso |
| Engenharia de IA | Especifica requisitos de consumo, integra e testa os sistemas |

Um colaborador pode desempenhar mais de um papel, mas a autoridade precisa estar registrada.

## Em projetos de dados

A área de negócio define e aprova o significado; as equipes de dados verificam como esse significado aparece nas tabelas e nos cálculos.

| Pergunta | Quem responde |
|---|---|
| “O que é uma venda confirmada para este processo?” | Quem aprova o indicador e especialistas do domínio |
| “Qual tabela e qual campo implementam esse conceito hoje?” | Responsável pelo dado, com validação do negócio |
| “Qual cardinalidade, fuso e regra temporal foram verificados?” | Engenharia ou analytics responsável pelo modelo de dados |
| “A consulta de referência reproduz o indicador aprovado?” | Dados e negócio em conjunto |
| “A IA recupera a fonte, respeita o escopo e se abstém quando deve?” | Engenharia de IA, com os critérios fornecidos pelo domínio |

Quem aprova a definição **não precisa saber YAML**. O engenheiro pode ajudar a estruturar o documento, mas não deve inventar o conteúdo.

## Modelo simplificado de matriz RACI

| Atividade | Especialista | Quem aprova | Governança | Engenharia IA |
|---|---|---|---|---|
| Explicar regra de negócio | **R** | A | C | C |
| Aprovar definição | C | **A/R** | C | I |
| Definir precedência entre fontes | C | R | **A** | C |
| Testar a aplicação em RAG ou agente | C | C | I | **A/R** |
| Atualizar conteúdo de negócio | **R** | **A** | C | I |

R = executa; A = responde pela aprovação final; C = consultado; I = informado. **Exemplo metodológico**, não organograma ou política corporativa.

## Quando surgem documentos contraditórios

Não escolha a fonte mais recente automaticamente: data de publicação não garante autoridade. Registre o conflito, a origem, o impacto e o responsável pelo desempate. Se não houver decisão, mantenha o conflito registrado como não resolvido (`unresolved`).

## Governança editorial do portal

O mantenedor é responsável pelos modelos, exemplos e bibliografia deste site. Ele **não é responsável** por aprovar políticas, indicadores ou processos específicos de organizações que adotem o método.
