## 2. O que perguntar ao especialista?

| Pergunta de elicitação | Lacuna descoberta |
|---|---|
| “Conversão” significa pedido criado, pago, confirmado ou entregue? | Evento que conta como numerador |
| “Visita” representa sessão, usuário ou acesso à página? | Unidade do denominador |
| Existem pedidos de teste ou cancelados? | Critérios de exclusão |
| O indicador vale para app, web e loja física? | Escopo e canais |
| Como fechar um mês com eventos atrasados? | Janela temporal e atualização |
| Qual dashboard é a referência quando os valores divergem? | Fonte oficial e autoridade |
| Quem pode mudar a definição? | Responsabilidade e versionamento |

## 4. Como isso se conecta ao banco de dados?

Imagine uma tabela `fact_orders(order_id, status_code, created_at)` e outra `fact_sessions(session_id, channel, event_time)`. O schema revela nomes e tipos, mas não esclarece automaticamente:

- Se `status_code='C'` significa confirmado, cancelado ou concluído;
- Se `created_at` usa UTC ou um fuso comercial;
- Se `session_id` representa uma sessão em todos os canais;
- Se há uma relação válida entre pedidos e sessões para a granularidade escolhida;
- Se contagens devem ser deduplicadas antes do cálculo.

Essas informações exigem **documentação semântica adicional**, associada à documentação de KPI. Consulte [o módulo de semântica de dados](../../dados/semantica/).

## 5. Cinco perguntas para testar a documentação

| Pergunta ao sistema | Comportamento desejado se a documentação estiver completa |
|---|---|
| “Qual a conversão no mês?” | Aplicar a métrica oficial do canal, período e população solicitados |
| “A conversão mobile está subindo?” | Distinguir mobile web de app ou solicitar contexto |
| “Posso incluir pedidos cancelados?” | Responder segundo uma regra aprovada, com sua fonte |
| “Qual dashboard está certo?” | Consultar a hierarquia de fontes definida pela organização |
| “Qual é a métrica oficial deste documento ainda pendente?” | **Não apresentá-la como aprovada** |

No [laboratório Aurora](../../exemplos/analytics-integrado/), os mesmos dados produzem 25% de sessões convertidas, mas 50% de pedidos confirmados por sessão elegível. A distinção precisa ser explícita.

Não estamos testando se um LLM específico acertaria essas perguntas. Estamos avaliando **se a documentação contém os elementos necessários** para que uma implementação possa ser construída e testada.
