<p class="editorial-lead">Uma análise correta começa no significado da pergunta</p>

A loja Aurora quer documentar a **taxa de sessões web convertidas**. A pergunta parece simples, mas uma sessão pode conter mais de um pedido. Uma contagem de pedidos é diferente de uma contagem de sessões.

O laboratório usa uma amostra sintética pequena, para que cada cálculo possa ser refeito à mão.

## 1. As duas tabelas

`demo_sessions`: uma linha por sessão.

| session_id | channel | is_internal | session_date |
|---|---|---|---|
| S1 | web | 0 | 2026-10-01 |
| S2 | web | 0 | 2026-10-01 |
| S3 | web | 1 | 2026-10-01 |
| S4 | app | 0 | 2026-10-01 |
| S5 | web | 0 | 2026-10-01 |
| S6 | web | 0 | 2026-10-01 |

`demo_orders`: uma linha por pedido.

| order_id | session_id | status_code |
|---|---|---|
| O1 | S1 | CONFIRMED |
| O2 | S1 | CONFIRMED |
| O3 | S2 | CANCELED |
| O4 | S3 | CONFIRMED |
| O5 | S4 | CONFIRMED |
| O6 | S5 | TEST |

O período do exemplo é **1º de outubro de 2026**.

## 2. O schema sozinho não resolve a questão

Um modelo consegue identificar `session_id`, `status_code` e `channel`. Mas não sabe, sem documentação adicional, se `CONFIRMED` é uma conversão válida, se sessões internas entram, se uma sessão com dois pedidos conta uma ou duas vezes, se `session_date` está em UTC ou no fuso da loja, nem se `session_id` identifica uma sessão do mesmo jeito na web e no app.

A definição aprovada pela Aurora estabelece:

- Sessões elegíveis: `channel='web'` e `is_internal=0` → S1, S2, S5 e S6 (**4 sessões**).
- Sessões convertidas: sessões elegíveis com pelo menos um pedido `CONFIRMED` → somente S1 (**1 sessão**).
- Indicador: `sessões_convertidas ÷ sessões_elegíveis × 100` → **25%**.

Isso é uma definição de **taxa de sessões convertidas**, não uma taxa genérica universal de e-commerce.

## 3. A armadilha da junção

<JoinDiagram />

S1 possui dois pedidos confirmados. Se uma consulta conta **pedidos confirmados por sessão elegível**, encontra **2 ÷ 4 = 50%**. Esse cálculo pode estar matematicamente correto para um **indicador diferente**, mas não corresponde à nossa pergunta, que mede sessões únicas convertidas.

A relação documentada entre `demo_sessions` e `demo_orders` é **um-para-muitos**. Essa informação, e não somente o nome da chave, explica o risco de duplicidade. O erro está em não declarar a **granularidade**, o que uma linha representa. Antes da junção, uma linha é uma sessão; depois, é um pedido. Contar linhas depois da junção conta pedidos, mesmo que a pergunta fale de sessões. O documento de [relacionamento entre tabelas](../../templates/relacionamento/) é onde isso fica escrito.

## 4. SQL de referência para esta amostra

```sql
WITH eligible_sessions AS (
  SELECT session_id FROM demo_sessions
  WHERE channel = 'web' AND is_internal = 0
    AND session_date = '2026-10-01'
),
converted_sessions AS (
  SELECT DISTINCT o.session_id
  FROM demo_orders AS o
  JOIN eligible_sessions AS s ON s.session_id = o.session_id
  WHERE o.status_code = 'CONFIRMED'
)
SELECT ROUND(
  100.0 * (SELECT COUNT(*) FROM converted_sessions)
  / NULLIF((SELECT COUNT(*) FROM eligible_sessions), 0),
  2
) AS converted_session_rate;
```

A consulta vale para esta amostra. Não a copie para dados de produção sem revisar a semântica e a estrutura reais.

## 5. O dashboard precisa repetir o mesmo significado

Um dashboard com o cartão “Conversão web” deve apontar ao documento do indicador e registrar seus filtros, a data e a regra de contagem. Se não o fizer, dois dashboards podem mostrar 25% e 50% sem que o leitor perceba que estão respondendo a perguntas diferentes.

Isso é precisamente o problema que a [documentação semântica de datasets](../../templates/dataset/), [relacionamentos](../../templates/relacionamento/) e [dashboards](../../templates/dashboard/) ajuda a prevenir.

## 6. Perguntas que o acervo deve sustentar

Sete perguntas sobre esta amostra formam o gabarito do laboratório: uma respondível (25%), duas de explicação (por que não 50%, e por que 01/10 não se compara com 10/09), uma ambígua e três sem número. Estão, com a resposta esperada de cada uma, em [Perguntas de referência](../../templates/casos-teste/).
