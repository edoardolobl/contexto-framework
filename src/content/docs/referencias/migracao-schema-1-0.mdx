Esta página é para quem já baixou um modelo da versão 0.x e quer saber o que mudou. O método não muda: as perguntas, os exemplos e os estados continuam os mesmos. O que muda é o formato do arquivo e o nome de alguns campos.

## O que mudou

- **O modelo é um Markdown com os campos no topo.** Entre duas linhas `---` ficam os campos com nome fixo; abaixo, a explicação de cada um em português. O `.yaml` passa a ser gerado desse topo, e por isso os dois arquivos nunca divergem. Veja [Como ler os campos](../../fundamentos/como-ler-os-campos/).
- **Todo modelo tem o mesmo cabeçalho, na mesma ordem**, com `schema_version: "1.0.0"`, que diz a versão do formato e não a do documento.
- **A intenção fica num bloco só, `intent`,** igual em todos os tipos: a pergunta de negócio que o documento responde (`intent.question`) e para que ele serve (`intent.purpose`).
- **O tipo do documento usa o nome do modelo**, como `kpi` ou `conceito`.
- **Um estado novo, Substituído** (`superseded`), para a versão cujo lugar foi tomado por outra do mesmo identificador. Obsoleto (`deprecated`) fica para o assunto que deixou de valer.
- **As perguntas em aberto têm um formato único**, com campo de resolução.
- **Os arquivos de Perguntas de negócio mudaram de nome**, para acompanhar o nome do tipo.

## Como migrar um documento seu

1. Baixe o modelo novo do mesmo tipo em [Modelos](../../templates/).
2. Copie suas respostas para os campos do topo, seguindo a tabela acima.
3. Escreva a pergunta de negócio em `intent.question`. Se ela ainda não está clara, registre isso como pergunta em aberto.
4. Passe cada pergunta em aberto para o formato novo, com `status: unresolved` até alguém resolver.

Mudar de formato não muda a versão do documento: a regra é a mesma, só está escrita em outro arquivo.
